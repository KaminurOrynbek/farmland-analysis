3. Methodology of the Work
3.1. Research Approach
This study adopts a system-oriented and experimental research approach that integrates machine learning techniques with geospatial data analysis for the purpose of automated agricultural land monitoring. The methodology is structured around the application of transfer learning for satellite image classification, combined with remote sensing data processing and interactive web-based visualization of analytical outputs.
The research can be classified as applied in nature, as its primary objective is the design, implementation, and evaluation of a functional end-to-end system rather than the derivation of purely theoretical models or algorithms. Applied research of this type is characterized by its orientation toward practical problem-solving within a specific domain — in this case, the automation of farmland condition assessment using publicly available satellite data and modern deep learning techniques. The experimental dimension of the study involves the training and fine-tuning of a machine learning model, the integration of geospatial processing components, and the empirical evaluation of system performance under realistic operational conditions.
The methodological framework is guided by three overarching principles. First, reproducibility: all data sources, model architectures, and processing procedures are selected from publicly available and well-documented resources, ensuring that the research can be independently verified and extended. Second, modularity: the system is designed as a collection of loosely coupled components — a machine learning module, a geospatial processing backend, and a frontend visualization interface — each of which can be developed, tested, and improved independently. Third, scalability: the architectural decisions made throughout the project are intended to support future extension of the system beyond its current prototype scope, including the integration of additional satellite data sources, expanded classification taxonomies, and broader geographic coverage.
The study does not aim to outperform state-of-the-art remote sensing models in benchmark accuracy. Rather, its contribution lies in demonstrating the feasibility of integrating transfer learning, geospatial data processing, and interactive web technologies into a unified, accessible analytical platform for agricultural monitoring — a combination that the existing literature addresses only partially.
3.2. System Architecture
The developed system follows a three-tier modular architecture consisting of a frontend interface layer, a backend processing layer, and a machine learning module. This separation of concerns ensures that each component can be developed, maintained, and scaled independently, while a well-defined API contract governs communication between layers.
Frontend Layer
The frontend is implemented using React, a component-based JavaScript framework that enables the construction of dynamic and responsive user interfaces. React was selected over alternative frameworks such as Vue.js or Angular due to its widespread adoption in the developer community, its mature ecosystem of geospatial and data visualization libraries, and its efficient virtual DOM rendering, which is particularly beneficial for applications that frequently update map-based visualizations in response to user interactions.
Geospatial rendering within the frontend is handled by Leaflet.js, an open-source JavaScript library for interactive map visualization. Leaflet enables efficient rendering of tile-based satellite basemaps, vector overlay layers derived from user-uploaded GeoJSON files, and color-coded analytical result layers. Its lightweight architecture and compatibility with a broad range of tile providers — including Sentinel Hub imagery endpoints — make it well-suited for the requirements of this web service. Users interact with the map to define areas of interest, upload field boundary files, trigger analysis requests, and inspect classification and vegetation index results returned by the backend.
Backend Layer
The backend is developed in Python using the FastAPI framework, which serves as the central orchestration layer responsible for handling all API requests, coordinating data flow between system components, and managing communication with external satellite data platforms. FastAPI was selected due to its high performance relative to alternative Python web frameworks such as Flask and Django REST Framework, its native support for asynchronous request handling, and its automatic generation of interactive API documentation through OpenAPI specification compliance. These properties are particularly relevant for a geospatial web service in which API endpoints must handle potentially large raster data payloads and coordinate multiple sequential processing operations within a single request lifecycle.
Geospatial data processing within the backend is performed using GeoPandas for vector data operations — including the validation, area computation, and centroid calculation of user-uploaded field boundary polygons — and Rasterio for raster data manipulation, including spatial clipping of satellite imagery to field extents and the computation of spectral band arithmetic for vegetation index calculation.
Machine Learning Module
The machine learning module is responsible for land-use and land-cover classification of satellite image patches. It encapsulates the pretrained and fine-tuned ResNet-50 model, exposes a prediction interface callable by the backend, and manages the preprocessing transformations required to convert raw image data into model-compatible input tensors. The module is implemented using PyTorch and operates as an integrated component of the backend processing pipeline rather than as a separately deployed service, simplifying deployment and reducing inter-component communication overhead in the prototype implementation.
The interaction between these three layers follows a request-driven pattern. A user action in the frontend — such as uploading a GeoJSON file and initiating an analysis — triggers an HTTP request to the backend API. The backend retrieves the corresponding satellite imagery, processes the geospatial data, invokes the machine learning module for classification inference, computes vegetation indices, and returns a structured JSON response containing classification results and index values. The frontend receives this response and updates the map visualization and statistics panel accordingly.
3.3. Data Processing Workflow
The data processing workflow is structured as a sequential multi-stage pipeline that transforms raw satellite imagery and user-supplied geospatial boundaries into meaningful agricultural analysis outputs. Each stage of the pipeline is designed to handle a specific transformation, with well-defined inputs and outputs that ensure compatibility between successive processing steps.
Stage 1 — Satellite Imagery Retrieval
In the first stage, satellite imagery is retrieved from Google Earth Engine (GEE) using the GEE Python API. Image collection queries are parameterized by three user-defined criteria: the geographic bounding box of the uploaded field boundaries, the temporal range of interest, and a maximum cloud coverage threshold expressed as a percentage. The cloud coverage filter is applied at the collection level to exclude images in which cloud contamination would compromise the quality of spectral analysis. From the filtered collection, a composite image is generated to produce a spatially complete and atmospherically consistent raster for the area of interest.
Stage 2 — Spatial Clipping
In the second stage, the retrieved raster imagery is spatially clipped to the boundaries of each individual agricultural parcel defined in the user-uploaded GeoJSON file. This operation is performed using the Rasterio library's masking functionality, which applies each polygon geometry as a spatial mask to the raster, retaining only the pixel values that fall within the parcel boundary and setting all external pixels to a no-data value. Clipping ensures that subsequent processing and analysis are restricted to the relevant agricultural areas, preventing surrounding land cover types from influencing classification and index computation results.
Stage 3 — Vegetation Index Computation
In the third stage, vegetation indices — NDVI and EVI — are computed from the clipped multispectral raster data using the spectral band arithmetic formulas described in Section 2.1.5. Band values are extracted as numerical arrays from the relevant spectral channels of the raster, and index values are computed pixel-wise using NumPy array operations. The resulting index arrays are stored as additional single-band raster layers spatially aligned with the clipped imagery.
Stage 4 — Preprocessing for Model Inference
In the fourth stage, the clipped imagery is preprocessed into a format compatible with the ResNet-50 classification model. This involves resizing each image patch to 224×224 pixels using bilinear interpolation, applying per-channel normalization using the ImageNet mean and standard deviation values (mean: [0.485, 0.456, 0.406]; std: [0.229, 0.224, 0.225]), and converting the normalized array to a PyTorch tensor of shape (C, H, W), where C denotes the number of spectral channels. A batch dimension is added to produce a tensor of shape (1, C, H, W) suitable for single-sample inference.
Stage 5 — Model Inference and Result Delivery
In the final stage, the preprocessed tensor is passed to the fine-tuned ResNet-50 model, which produces a probability distribution over the 10 EuroSAT land-cover classes via a softmax output layer. The predicted class is determined as the argument of the maximum probability. The predicted land-cover label, together with the computed NDVI and EVI values, is returned to the backend API handler, serialized as a JSON response, and transmitted to the frontend for visualization as a map overlay and summary statistics panel.
3.4. Machine Learning Model
The machine learning component of the system is based on a transfer learning approach using a ResNet-50 convolutional neural network pretrained on the ImageNet dataset. The selection of ResNet-50 as the base architecture is motivated by several considerations. ResNet-50 introduces residual connections — shortcut pathways that allow gradients to flow directly through the network during backpropagation — which effectively mitigate the vanishing gradient problem in deep networks and enable stable training of architectures with 50 or more layers. This depth allows the network to learn hierarchical feature representations of increasing abstraction, from low-level spectral and textural features in early layers to high-level semantic patterns in deeper layers. These properties make ResNet-50 particularly well-suited for satellite image classification tasks, where the discrimination of spectrally similar land-cover classes requires the extraction of nuanced and composite visual features.
The transfer learning procedure follows a fine-tuning strategy in which the pretrained convolutional backbone is retained and its final fully connected classification layer is replaced with a new linear layer whose output dimension corresponds to the 10 classes of the EuroSAT dataset. During fine-tuning, the weights of the convolutional backbone are updated at a reduced learning rate to preserve the low-level feature representations acquired during ImageNet pretraining, while the newly added classification head is trained at a higher learning rate to adapt rapidly to the target domain. This differential learning rate strategy reduces the risk of catastrophic forgetting — the undesirable overwriting of pretrained representations — while enabling effective domain adaptation.
Training is conducted using the cross-entropy loss function, which measures the divergence between the predicted class probability distribution and the true one-hot encoded class label. The Adam optimizer is employed for parameter updates due to its adaptive learning rate mechanism, which adjusts the effective step size for each parameter individually based on the first and second moments of the gradient history. This makes Adam particularly robust to variations in gradient magnitude that are common in transfer learning scenarios where different layers of the network are trained at different effective learning rates.
Input images are resized to 224×224 pixels and normalized using ImageNet statistics prior to being passed to the model. Data augmentation — including random horizontal and vertical flipping, random rotation within a 15-degree range, and random brightness and contrast jitter — is applied stochastically to the training batch at each iteration to increase the effective diversity of the training data and reduce overfitting. The output of the model is a 10-dimensional softmax probability vector, from which the predicted land-cover class is derived as the index of the maximum probability value.

3.6. Evaluation Approach
The evaluation of the system is conducted at two levels: the performance of the machine learning model and the functional correctness of the integrated web service.
Model Evaluation
The classification performance of the fine-tuned ResNet-50 model is assessed on the held-out test subset of the EuroSAT dataset, comprising 10% of the total samples selected through stratified sampling. The following quantitative metrics are computed:
Overall Accuracy measures the proportion of correctly classified samples across all classes and provides a general indicator of model performance. However, as a single aggregate metric, overall accuracy may be misleading in cases of class imbalance, and is therefore complemented by per-class metrics.
Precision, Recall, and F1-Score are computed per class and averaged using both macro and weighted averaging schemes. The F1-score — the harmonic mean of precision and recall — is particularly informative for evaluating classification performance on individual land-cover classes that may be of unequal importance for agricultural analysis.
Confusion Matrix analysis is performed to identify specific patterns of misclassification between land-cover classes. This is particularly valuable for understanding which pairs of agricultural classes — for example, Annual Crop versus Permanent Crop — are most frequently confused by the model, and for guiding future improvements to training data or model architecture.
System Evaluation
The functional evaluation of the integrated web service assesses the correctness and consistency of the end-to-end data processing pipeline, including satellite imagery retrieval, spatial clipping, vegetation index computation, and result visualization. The system is tested using sample GeoJSON field boundaries and corresponding satellite imagery to verify that all pipeline stages produce outputs consistent with expected values. Response time and system responsiveness under standard usage conditions are additionally assessed to evaluate the practical usability of the platform.
3.7. Summary
The methodology presented in this chapter defines a comprehensive and reproducible framework for integrating transfer learning, geospatial data processing, and web-based visualization into a unified system for automated agricultural land analysis. The modular three-tier architecture ensures separation of concerns and supports future extensibility, while the structured multi-stage data processing pipeline guarantees consistent and interpretable analytical outputs. The combination of the EuroSAT benchmark dataset, the ResNet-50 transfer learning model, and cloud-based satellite data platforms demonstrates the feasibility of developing practical and scalable solutions for modern precision agriculture monitoring without requiring specialized hardware or proprietary data resources.
